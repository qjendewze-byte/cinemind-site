## 1. 不具合1：メタディスクリプション未設定（最優先）

### 1-1. 事実確認：全24記事で発生

公開記事24本すべてのHTMLを取得し、`<meta name="description">` を確認しました。全記事で、本文冒頭に貼られているYouTube埋め込みのURLがそのまま説明文の先頭に出ています（例: `captain2` → `https://youtu.be/V_zaDDPM9qY?si=... あらすじ アベンジャーズの戦いから...`）。

### 1-2. 特定した post meta キー名

**`ssp_meta_description`**

根拠: SEO SIMPLE PACKの開発元リポジトリ（GitHub `ddryo/seo-simple-pack`、サイトに導入されている v3.6.2 と同一系統のソース）を取得し、直接確認しました。

```php
// class/metabox.php
const POST_META_KEYS = [
    'robots'      => 'ssp_meta_robots',
    'title'       => 'ssp_meta_title',
    'description' => 'ssp_meta_description',
    'keyword'     => 'ssp_meta_keyword',
    'canonical'   => 'ssp_meta_canonical',
    'image'       => 'ssp_meta_image',
];
```

投稿編集画面の「Description of this page」欄は、このキーに対して `update_post_meta()` / `get_post_meta()` を使う単純な文字列（1件のみ、シリアライズなし）です。

さらに `class/output.php` の `generate_description()` で、フロント表示時の優先順位が次の通りであることも確認しました。

1. `ssp_meta_description`（投稿ごとのメタボックス）に値があればそれを使う
2. 空の場合、投稿タイプ別のデフォルト設定（`post_desc` など、SEO SIMPLE PACK設定画面の「投稿ページ」タブで設定）にフォールバックする

24記事とも1が空のため2にフォールバックし、デフォルトのディスクリプション生成テンプレート（本文の先頭を抽出する設定になっていると見られる）が、本文冒頭のYouTube URLをそのまま拾っている、というのが不具合の発生メカニズムです。

**確認できなかったこと**: 現在「投稿ページ」タブに設定されているデフォルトテンプレートの実際の値（`post_desc` オプションの中身）。この設定はWordPress管理画面（wp-admin）でのみ確認・変更でき、Application PasswordによるREST API認証では管理画面にログインできないため、今回のセッションでは確認していません。

### 1-3. REST APIから読み書きできるか → 結論：書き込み不可（未登録メタキーのため）

**検証方法**:

1. `GET /wp/v2/posts/471?context=edit&_fields=id,slug,meta` で公開記事のmetaフィールドを確認 → `ssp_meta_description` は存在しない（登録されていないキーはREST APIのmetaフィールドに一切現れません）
2. プラグインソースを `register_post_meta` / `register_meta` / `show_in_rest` で検索 → **該当箇所ゼロ**。SEO SIMPLE PACKはこのキーをREST APIに一切公開していません
3. 使い捨て下書き（ID 496、タイトル「【検証用・削除予定】meta description test」）を作成し、`POST /wp/v2/posts/496` で `{"meta":{"ssp_meta_description":"..."}}` を送信 → HTTPステータスは200（エラーにはならない）が、レスポンスの `meta` オブジェクトに `ssp_meta_description` は含まれず、直後の `GET ?context=edit` でも値は反映されていませんでした
4. 検証終了後、`DELETE /wp/v2/posts/496?force=true` で完全削除し、`GET` で404になることを確認済み

**結論**: WordPress REST APIのmetaフィールドは、`register_meta`（`show_in_rest: true`）で明示的に登録されたキーしか読み書きできません。SEO SIMPLE PACKはこのキーを登録していないため、**REST APIだけでは`ssp_meta_description`を読み書きできません**。書き込みリクエストはエラーにならず黙って無視される（サイレントに何も起きない）ため、気づきにくい不具合です。

### 1-5. 推奨する手段

**A（Code Snippetsで`register_post_meta`を追加）を推奨します。**

理由:

- B（設定画面のデフォルト変更）は暫定的な改善にしかならない。デフォルトテンプレートを直しても、それは「全記事共通の型」であり、CLAUDE.mdの方針にある「テンプレートの使い回しにしない、記事ごとに具体性のある説明文を書く」という目的とは矛盾する。あくまで保険として設定しておく価値はあるが、主策にはならない
- C（本文構成の変更）は24記事全部の編集が必要で、リライト作業と規模が変わらない。しかも効果は「自動生成の質が上がる」程度で、狙ったキーワードを意図的に盛り込めない
- Aは一度スニペットを追加すれば、以後は記事ごとに作り込んだメタディスクリプション（本レポート1-6参照）をREST API経由で正確に反映でき、今後書く新記事にも同じ仕組みがそのまま使える。ユーザーの手作業も「スニペット追加の承認」だけで済む

なお、Aを実行するにはCode Snippetsへのスニペット追加という「プラグインの設定変更」が発生します。CLAUDE.mdの制約により、これは本レポートの範囲外（今回は調査のみ）とし、**次のステップとしてユーザーに承認を得てから実施**します。
