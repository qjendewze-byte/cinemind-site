# 作業の進め方（2026-10-08 から）

ユーザーが管理しなくても回るように、担当を分けて統括が回す。

## 担当

| 担当 | 誰 | やること |
|---|---|---|
| 統括 | メインセッション | ボードの管理、優先順位、担当への発注、WordPressへの下書き入稿、ユーザーへの報告 |
| リサーチ役 | Sonnet（`docs/roles/researcher.md`） | 需要・上位記事・公式情報・事実一覧・図の案 → 調査ブリーフ |
| 記事作成役 | Sonnet（`docs/roles/writer.md`） | ブリーフから原稿と図 |
| 事実確認役 | Opus（`docs/roles/factcheck.md`） | 事実を一次情報で確認 |
| SEO・編集役 | Opus（`docs/roles/seo-editor.md`） | 上位記事との比較、導入、AIっぽさ、title/meta |

書いた本人に検証させない。発注時は、担当の定義ファイルを最初に読ませる。

## 流れ（記事1本）

1. 統括がボードから1本選び、リサーチ役に発注 → `docs/briefs/<slug>.md`
2. 記事作成役に発注 → `articles/<slug>.md`
3. 事実確認役とSEO・編集役に**同時に**発注
4. 統括が指摘を反映（大きければ記事作成役に差し戻し）
5. **合格の基準: 事実面・編集面とも8点以上。** 届かなければ3〜4をもう一度（最大3巡。3巡で届かなければボードに「保留」と理由を書く）
6. 統括がWordPressに**下書き**で入稿し、ボードを「承認待ち」に

## ユーザーにお願いすること（これだけ）

- **公開してよいかの承認**（ボードの「承認待ち」）
- 方針の判断（新しい分野に広げる、お金がかかる、公開済み記事を大きく変える など）

公開、削除、公開済み記事の変更、アフィリエイト登録は、承認なしにやらない。

## 報告

- 1本終わるごと、またはまとめて1日1回。数行で、結果とお願いだけ
- 詳しい経緯はボードと各ファイルに書き、報告には書かない

## ボード

`docs/board.md`。統括が常に最新に保つ。
